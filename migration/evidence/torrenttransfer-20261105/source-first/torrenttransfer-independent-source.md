## Transfer algorithm and every filter

`transfer` begins log, validates again, resolves both services and aborts if either missing/inactive (`679–688`). Resolution logs warnings only, not persistent system messages (`141–152`). Completed-torrent query is backend helper `get_completed_torrents()` (`690`): false/None/[] all log no completed and return, with no completion notification (`691–695`). Plugin applies no light-media tag/ownership restriction; this plugin explicitly transfers source completed tasks selected by its own filters.

Selection loop preserves source enumeration order (`698–766`). At the start of each selection iteration, Event aborts whole transfer (`700–702`). No Event checks exist in later side-effect loop. Per torrent:

1. Extract hash/save_path. For QB, dict.get hash and save_path; for every other type, TR-style hashString and download_dir. Missing/error→empty string (`992–1000`,`1027–1035`). Hash is not validated/case-normalized.
2. If nopaths truthy and save_path truthy, split nopaths on literal newline; normalize save/path via `os.path.normpath`, then literal `.startswith` (`709–718`). This is case-sensitive Linux prefix, **not path-boundary containment**; `/media/a` excludes `/media/abc`; no line trimming/empty-line removal. Blank line normalizes to`.` and can match relative paths. It tests original save directory, not mapped directory and not content file paths.
3. QB labels: split torrent.tags on comma and strip every source tag; TR labels: raw `torrent.labels or []`; exception→[] (`1003–1012`). QB category strip string; TR always empty (`1015–1024`). `['']`,[] orNone labels are normalized empty (`725–727`); other mixed lists containing empty remain nonempty.
4. includecategory truthy requires exact source category membership in raw comma-split string (`730–734`), no trim/casefold. TR can match empty category if configured list includes an empty token.
5. Empty labels require transferemptylabel true; allowed empty tasks **bypass nolabels and includelabels** (`735–739`). Nonempty labels are rejected if **any** raw comma-split nolabels entry is present (`741–749`); includelabels requires **every** configured raw comma-split label present (`751–759`). Whitespace/case meaningful for config tokens. Path and category still apply to untagged tasks.
6. Candidate captures original torrent object, hash and save_path (`762–766`). No data/history read participates in selection/dedupe; no size/age/time/ratio/name/status rule beyond helper completion query.

Candidates count is `total` and initializes success/fail/skip/del_dup0 (`769–780`). For each candidate (`783–911`), in this exact order:

1. Construct `Path(fromtorrentpath)/f"{hash}.torrent"`. Missing source file increments fail and skips before destination duplicate lookup (`784–790`). File name is direct hash, without TR alternate filename lookup or client export API. A missing source path can fail later despite one-shot validation succeeding. File present but unreadable `read_bytes` may raise and abort entire transfer.
2. Query destination by original hash; discard the query's second error/status result (`793`). Any truthy torrent result is duplicate. If deleteduplicate true, call source delete_torrents(delete_file=False,ids=[source_hash]), increment del_dup regardless returned bool; otherwise skip++. Both skip add/path/tracker/history/recheck; no source data file deletion (`794–804`). deletesource setting does not govern this branch.
3. Convert original save_path using roots; false result→fail++/skip (`806–814`). Empty save_path returns topath as-is; if either root false return original save_path unchanged; with both roots nonempty Linux normpath each and replace backslashes with slash, then if save_path startswith from_root replace **first literal occurrence** (`1054–1070`). Prefix need not terminate on path separator. Mismatch or caught exception→None. Source roots are not used for local file access checks. No physical data movement/hardlink/copy happens.
4. QB source only: read torrent bytes, empty→fail++; bdecode and read `announce`, catch decode/get failure→fail++ (`817–831`). Existing truthy announce leaves bytes untouched even if announce-list missing. False/missing announce requires hash.fastresume file even if announce-list already exists; missing fastresume→fail++ (`833–840`). Read/bdecode fastresume inside catch; if trackers is a nonempty list with truthy first tier, set announce=trackers[0][0]; if >1 tier OR >1 tracker first tier, set announce-list to whole trackers; encode and write `TEMP_PATH/hash.torrent` (`842–859`). Do not rewrite source seed. A missing/empty/wrong-type trackers structure without exception does **not** fail: original tracker-less torrent proceeds. Wrong tracker tier types may index unexpectedly or throw; thrown error increments fail (`860–863`). Repaired temporary file is retained; plugin has no cleanup or per-instance temp filename. TR source skips all bdecode/repair entirely, forwarding file bytes.
5. Add bytes from selected original/temp file via __download (`865–875`). False returned ID→fail++; no recheck/source delete/history. Unsupported destination returns None after error (`670–671`). Source service is looked up again inside __download; it may now be missing even though outer lookup succeeded; accessing from_service.type can then raise when retention enabled.
6. On returned ID, QB destination: skipverify false → recheck_torrents(ids=[id]) (ignore result) then queue ID; skipverify true+autostart true→queue; skipverify true+autostart false→no recheck/no queue. TR destination always queues and relies on automatic client verification. Queueing occurs for QB verify and TR even when autostart false (`880–894`).
7. If deletesource true, delete only source task with delete_fileFalse, ignoring returned bool. This happens **before verification completion**, not after confirmation of full data (`896–899`). Success++ then save history (`901–911`). Exceptions before save abort whole job without complete summary; no transaction/rollback.

After loop, if success>0 AND autostart, check_recheck immediately (`913–914`). If notify, post `NotificationType.SiteMessage`, title `【转移做种任务执行完成】`, exact text `总数：{total}，成功：{success}，失败：{fail}，跳过：{skip}，删除重复：{del_dup}` (`917–922`). No notification when no candidates or no completed tasks. Duplicate removal counts only del_dup; each candidate counts once among success/fail/skip/del_dup absent exceptions. Post-message errors are not caught. No artificial per-torrent notifications.

## Add protocol, recheck queue and error semantics

__download rejects missing service/instance (`619–620`) and resolves source again (`622`). QB creates random alphanumeric marker length10 through StringUtils (`625–626`). retainoldtag true yields `list(set(source_labels+configured_tags+[marker]))` (order unspecified, deduplicated); false yields configured_tags+[marker] (duplicates retained) (`627–632`). remainoldcat true uses extracted QB source category or empty TR category; false None (`633–637`). Call add_torrent(content=bytes,download_dir=converted,is_paused=True,tag=list,category=value,is_skip_checking=skipverify) (`638–643`). No explicit is_auto parameter is set despite comment about closing auto-management. It tests add result truthiness and, if true, asks helper get_torrent_id_by_tag(tags=marker); no hash returned→failure (`644–652`). No marker removal/retry inside plugin; helper owns them. TR retainoldtag uses deduplicated source+configured tags; false configured_tags; add paused with labels, no category/skipverify parameter; return torrent.hashString orNone (`653–668`). QB/TR source/destination all4 combinations remain supported.

Queue dict `_recheck_torrents[destination_name]` lazily creates list then appends, no dedupe (`927–932`). `check_recheck` returns if whole map empty, current destination missing, or running true (`938–943`). It resolves current configured destination, returns on unavailable instance or no pending IDs under that **current** service name (`945–955`); entries for previous destination remain dormant. It sets running true before query (`960–962`) and ignores query's error second result.

Truthy query list: source-style hash extraction by destination type, then can_seeding check. QB can seed exactly state `pausedUP` or `stoppedUP`, independent of progress fields; TR requires `torrent.status.stopped` AND `percent_done==1` (`1038–1047`). All extracted eligible hashes are sent to start_torrents in one call, result ignored; queue becomes set(oldIDs)-set(startedIDs), so order/duplicates are not preserved (`963–981`). `None` list logs query failure and retains queue (`983–984`); empty list clears queue (`985–987`). A helper may return [] on error: ignoring the error flag is a real compatibility issue, not equivalent to None branch. running resets false at normal end (`989`), but **no finally**: a raised query/start/error leaves running true permanently until recreated/reset externally. False start result still removes IDs. A torrent missing from a nonempty result remains queued indefinitely. Periodic checker does not test autostart itself; it is registered only when autostart true, but direct call can start eligible queued tasks regardless.

No transfer-running lock exists. Separate public cron and private one-shot may overlap. check_recheck has only bool gate, not lock. Event is tested only in selection. Stop catches exceptions; if scheduler not running it removes jobs/drops reference without setting event. If shutdown raises after set, clear may never execute. Queue and running flag are not cleared by stop/init. There is no retry policy for transfer adds/files except future cron reruns; source failures commonly increment fail, but filesystem reads outside narrow catches, backend exceptions, helper/source retention errors and data-save failures escape whole operation.

## Storage and files

Only plugin `save_data`: key `source_service.name + "-" + original_hash`, value exactly `{to_download:destination_service.name,to_download_id:returnedID,delete_source:configuredFlag,delete_duplicate:configuredFlag}` (`904–911`). No timestamp/name/path, notification report or full task is saved; no history display/reset API, no history read/dedupe/recovery, no queue persistence, no deletion of historical keys. Reference `PluginDataOper.save` is per-plugin-ID key upsert; repeated successful same source/hash overwrites value, changing destination does not change key. Preserve existing record shape and instance namespace during migration; it is not authorization to replay writes.

Reads local source hash.torrent, conditional QB hash.fastresume; writes repaired torrent only to host global TEMP_PATH/hash.torrent. Does not use plugin get_data_path, write original backups or move actual payload files. Deleting source/duplicate task always sends delete_fileFalse; destination tasks never deleted. Original backup directory and mapped data directories are independently configured; no recursive scan, export fallback or mount auto-discovery.
